# CW 完善提案：从「存在性验收」升级到「保真 + 生命周期验收」

> **提交对象**：上游 change-workflow（CW）工具包维护方
> **提出背景**：md-bundle `editor-doubao-parity` + md-bundle-v2 交付后，用户实测反馈"功能堆砌、UI/UE 很差"
> **结论一句话**：现有 QG-1..7 / DQ-1..8 已经能拦住"功能**没接上**"，但拦不住"功能**接上了、体验烂**"。缺口在四类断言与一个上游环节（学习层）。
> **最后更新**：2026-10-03

## 3. 根因：链条分析（缺口逐层上移，源头在 L-1）

```
L-1 学习层   一手观察缺失 + 无证据留存 → 产物不可核验        ← 真正的源头
     │        （学习层自注"表格插入后编辑能力未展示"）
L0  规格层   学习空白被"想当然"补上；生命周期/视觉结果仍不写
L1  AC       复述成"存在性"
L2  实现     实现动词，不打磨状态机（能插入，不管插入后长相/怎么退/怎么清）
L3  测试     presence 断言；测不出"真单元格编辑"vs"整表塌陷"
L4  验收     用存在性自证通过（假手动 QA）
```

### 3.1 学习层（L-1）：源头污染
- **一手证据为零**：`editor-wysiwyg-design-v3.md` 写"从截图分析"，但 `find *豆包* / *doubao*` 零命中——无截图/录屏/来源，不可核验、不可复现。
- **自认没学到，却没补研究**：§0 表格行原文 `插入后编辑能力未展示`；分栏行 `仅布局，无内容感知`。
- **"可核验"名不副实**：`editor-wysiwyg-design.md §1.1「竞品深度分析（可核验）」` 列出 Sarala / MarkFlow / MD Editor Plus / Any Markdown，**唯独没有豆包**，且无一条来源。
- **发现未闭环**：`editor-v2-test-findings.md` 已记录"围栏显示 1 个 \`"等，**没转成规格/issue/测试** → 一个月后成品复发。

### 3.2 规格层（L0）：从高保真设计到弱规格的"翻译损耗"
- 设计 `editor-wysiwyg-design.md §3.5` 明确：单元格 contenteditable、Tab 移动、Esc/点击外部退出、列宽拖拽、排序。
- 落地规格 `editor-table-editing` 只剩一句 `Clicking a table cell SHALL place an editable cursor for that cell`——听上去等价，实测是"整表塌陷"。
- 结论：**规格允许用最弱实现满足**；生命周期与视觉结果**从未进规格**。

### 3.3 现有 QG 为何拦不住
| 现有门禁 | 它问了什么 | 为什么漏 |
|---|---|---|
| QG-1 用户层 AC | "是否有浏览器可观测陈述" | AC 写成"菜单可用"即可过；**未要求生命周期/保真** |
| QG-2 e2e 绑定 | "是否新增 e2e" | e2e 断言 presence 即可过；**未规定断言强度** |
| QG-4 真实路径 | "是否绕过 keymap"（鼓励断言计算样式） | 规则对了，但**默认断言仍是"元素存在"**；生命周期无对应断言形态 |
| QG-5 独立验证 | "是否有验证者原始输出" | 探针仍是 presence 类 → **与实现者共享同一盲区**；无视觉探针 |
| QG-6 集成 checkpoint | "用户现在能看到什么" | 记的是"看到功能"，**不检验"好不好用"** |
| 7.3 手动 QA | "真机手动" | **被自动化成 `qa-7.3-manual.spec.ts`**，无人看图，自证通过 |

> 与 `retro-editor-v2-quality` 的关系：那一轮是"12 票全绿、用户看不到变化"（**功能没接上**）；这一轮是"功能看到了、细节全烂"（**接上了但没保真**）。**同一条链的第四次复发**，症状换壳，根因是验收停在存在性。

## 5. 逐条提案（可直接落进 `quality-gates.md`）

### 5.1 【新增 QG-8】学习层证据门（L-1）

**规则**：任何以"对标 / 学习某产品 / 补齐某能力"为由的 change，其**学习产物必须满足三条**，否则不得进入 G0 拆票：

1. **一手证据留存**：截图/录屏/逐步观察，落在仓库可追溯路径（如 `docs/research/<topic>/`），带**日期 + 来源版本**。
2. **空白显式化**：学习时**未观察到的行为**必须标为 `open-question`，并**阻断**引用它的规格条目——**禁止用"想当然"补空白**。
3. **结论可核验**：删除"（可核验）"这类无来源话术；每条竞品结论要么给来源，要么标"待核验"。

**反例（本仓）**：`editor-wysiwyg-design-v3.md §0` 表格行自注"插入后编辑能力未展示"，却在 `editor-table-editing` 规格长出一条相关 requirement → 落地即缺陷。

**验证**：
```bash
# 学习产物是否有证据目录与来源
ls docs/research/*/ 2>/dev/null || echo "无学习证据目录 → 违规"
# 学习结论里的"未展示/未观察"是否被规格引用（应阻断）
grep -rn "未展示\|未观察\|待核验" docs/plans/*.md
```

---

### 5.2 【新增 QG-9】设计→规格保真门

**规则**：从设计稿/设计文档转 openspec requirement 时，**高保真设计不得被弱化**。判据：

- 设计里写明的**交互动词**（如"单元格 contenteditable 编辑"）必须在 requirement 中以**同等强度的可观测断言**出现，不得降级为"能编辑源码"这类弱表述。
- 设计里的**退出语义 / 导航（Tab） / 边界（Esc、点击外部）**必须逐条进 requirement 的 Scenario。

**反例（本仓）**：设计 §3.5 contenteditable/Tab/Esc → 规格弱化为一句"place an editable cursor"。

**验证**：review 时把设计稿与 requurement 并排，逐条勾"设计有此行为 → requirement 有对应 Scenario"；缺一条即违规。

---

### 5.3 【修订 QG-1】AC 三分类

现有 AC 只要求"浏览器可观测陈述"。**修订为**：用户可见票的 AC 必须覆盖三类，缺一即违规：

| 类别 | 形态 | 示例 |
|------|------|------|
| **① 存在**（现状） | 打开页面…之后…出现 X | "打开页面后，编辑器出现" |
| **② 生命周期**（新） | 覆盖 `打开·切换·取消·外部点击·空态·关闭` 六态，并断言**取消后不残留** | "弹出插入菜单后点击编辑器其它位置，菜单关闭；按 Esc 取消后文档不含触发字符 `/`" |
| **③ 保真**（新） | 可判真伪的**文本/像素**结果，而非"渲染正确" | "callout 卡片标头文本严格等于『注释』（不重复）"；"fenced code 行不含反引号字符" |

**固定格式（增补到 §四）**：
```
在 `pnpm --filter @md-bundle/web dev` 打开的页面中，
① <操作> 之后，<结果出现>；
② <触发> 之后，<浮层关闭 / 取消后无残留>；
③ <渲染> 之后，<文本严格等于 X / 计算样式为 Y>。
验证：apps/web/test/<feature>.spec.ts 通过。
```

---

### 5.4 【修订 QG-4】断言强度阶梯

现有 §五已禁止"断言元素存在"，但**默认实践仍是 `toHaveCount(1)`**。**修订为**：断言必须落在阶梯中**尽可能高**的层级：

```
1. 存在          toHaveCount(1)            ← 仅允许用于"确认挂载"，不得作为可见变更的唯一断言
2. 可见          getComputedStyle 非隐藏
3. 文本相等      toHaveText("注释")  / textContent === expected   ← 抓「注释 注释」「`js」这类
4. 状态往返      操作→反向操作→回到初始（如 取消后 doc 无残留 / 关闭后不残留）
5. 视觉          截图对比（见 QG-5 视觉探针）
```
**规则**：任何"渲染 / 装饰 / 插入 / 浮层"类变更，其 e2e **至少到第 3 级**；任何"可取消 / 可关闭"交互**必须到第 4 级**。

---

### 5.5 【修订 QG-5】探针类型 + 视觉探针 + 自证范围

- 探针类型清单**增加**：**视觉探针**（对关键态截图并**人工/多模态复核**，而非只截图存档）。
- 明确：**"元素存在 / count>0"不属于有效原始证据**（现有条款未点破这一点，实践中被当作证据使用）。
- 明确：**报告的"通过率"不得由 same-class 探针自证**（如 7.3 由自动化 spec 自证）。

---

### 5.6 【新增 收尾门】禁止伪造手动 QA + 生命周期黑盒巡检

- **禁止**：把"真机手动 QA"实现为自动化 spec（`qa-7.3-manual.spec.ts` 是反模式——名字即矛盾）。手动 QA 必须是**人/agent 真用一遍 + 逐步观察 + 截图 + 结论**。
- **收尾前固定动作**：跑一次**生命周期黑盒巡检**——按 D1..D10 这类清单，真机走一遍"打开→插入→编辑→切换→取消→关闭→空态→错误"，**发现问题即不允许收尾**。
- 巡检可作为 change 收尾的 checklist（见附录 A 模板）。

---

### 5.7 【新增 QG-10】发现闭环门

**规则**：任何**报告 / findings / 实测发现**里记录的缺陷，必须**转成 tracked issue 或规格条目**，否则该 change 不得标记完成。

**反例（本仓）**：`editor-v2-test-findings.md` 记录的"围栏反引号 / callout 无法续输"未转 issue → 复发。

**验证**：
```bash
# findings 里的每条缺陷是否能追到 issue
rg -n "^\|.*(反馈|问题|缺陷)" docs/plans/*findings*.md | wc -l   # 应 ≈ 已建 issue 数
```

## 7. 本提案如何自证有效（元验收）

1. **反向用例**：把 D1..D10 当测试集，逐条问"现行 QG 能不能拦"——**现状 0/10 可拦**；采用本提案后应 **≥8/10 可拦**（D7/D9 属实现/规格，由 QG-8/QG-9 拦）。
2. **回归验证**：在下一轮 change 上，**任何**用户可见票若不满足 5.3 的三分类 AC，QG-1 应同时报违规。
3. **不增加虚假负担**：视觉探针只在"渲染/装饰/插入/浮层"类变更强制；纯逻辑/文档票走既有豁免。
