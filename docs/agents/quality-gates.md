# 开发与测试质量门禁（QG）

> 适用范围：一切面向用户的 change / 缺陷修复，从 G0 拆票到 G2 合并的全流程质量校验。
> 生效日期：2026-09-20
> 配套：`docs/agents/retro-editor-v2-quality.md`（本规范的失败来源与根因分析）、`docs/agents/task-tracking.md`（任务跟踪）、`docs/agents/defect-workflow.md`（缺陷流程）、`.opencode/skills/change-workflow/SKILL.md`（G0-G4 gate 编排——本文件的 QG 挂载点）

---

## 一、背景

一次真实交付失败促成本规范：`editor-v2` change 的 9 个 PR 中，**8 个对 `apps/web/src` 零改动、对 e2e 零改动**，整个 change 期间新增 e2e 为 0。12 张票全部打勾，typecheck / lint / 单测 / CI **全绿**——而用户打开页面**看不到任何变化**。

根因不是开发能力不足，而是**「完成」的定义写在了库层而非用户层**，且**没有任何门禁对此提出异议**。门禁校验了代码的**形式正确性**，却没有校验功能的**存在性**与**可达性**。

本规范把该失败的根因固化为七条硬性门禁。完整根因分析见 `docs/agents/retro-editor-v2-quality.md`。

---

## 二、七条质量门禁

### QG-1 用户层 AC 强制

**规则**：一切面向用户的票，其 AC 必须包含至少一条**浏览器可观测陈述**（格式见 §三）。

**理由**：`editor-v2` 的 AC 写作「`getBlocks()` 返回块数组，4 条单测通过」「`AIProvider` 接口导出，类型检查通过」——全部可在**库层**满足。于是实施者用最省力的方式满足 AC：写模块 + 写单测，从不触碰 `App.tsx`。**这不是偷懒，是 AC 允许这么做。**

**违规真实案例**：AC「`getBlocks()` 返回块数组，4 条单测通过」→ 库层可满足，用户层不可见 → 12 张票全部打勾而应用零变化。

**如何验证**：
```bash
# 逐票检查 AC 是否含浏览器可观测陈述
gh issue view <票号> --json body --jq .body | grep -E "打开.*页面|dev server|apps/web/test/.*\.spec\.ts"
# 无输出 = 违规
```

---

### QG-2 e2e 绑定

**规则**：用户可见变更**必须**新增或扩展 `apps/web/test/*.spec.ts`；否则须在票上显式标注 `no-ui-impact`。

**理由**：CI 确实跑 Playwright，但 `editor-v2` change 期间**新增 e2e 为 0**——e2e 套件覆盖的是 **v1 旧行为**。于是「CI 绿」只等于「旧功能没坏」，与「新功能存在」**逻辑上无关**。绿色提供了**虚假信心**。

**加这条不增加基建成本**：CI 已经在跑 e2e，只是让覆盖跟上新功能。

**违规真实案例**：9 个 change PR 中 8 个 `apps/web/test` 改动为 0；`#154` 语义编辑态（11 个功能的核心）零 e2e。

**如何验证**：
```bash
# 检查分支是否新增/扩展了 e2e
git diff --name-only origin/main...<分支> | grep "apps/web/test/.*\.spec\.ts"
# 无输出且票上无 no-ui-impact 标注 = 违规
```

---

### QG-3 接线归属

**规则**：任何导出新 API 的票，必须显式指定「接线由哪张票负责」，并在该票 AC 中写出**具体接线位置**（如 `App.tsx` 的 `EDITOR_EXT`、`LeftRail`）。

**理由**：接线工作（注册扩展、挂载面板、注册命令）**不属于任何一张票的 AC** 时，在并行执行中**必然消失**——它是涌现属性，不是任何人的交付物。

**违规真实案例**：`EDITOR_EXT` 注册 7 个扩展、`StructurePanel` 挂进 `LeftRail`、命令进命令面板——这些在 12 张票全部完成后**根本没被做**，直到用户实测才发现。

**如何验证**：
```bash
# 本票导出的新 API 是否在 apps/web 有引用
git diff origin/main...<分支> -- packages/editor/src/index.ts | grep "^+export"
grep -rn "<新导出名>" apps/web/src/ || echo "无引用 → 必须指定接线票"
```

---

### QG-4 真实路径测试

**规则**：测试必须驱动**真实链路**；禁止绕过 keymap / 事件 / 公共 API 直接调内部函数。测 DOM 可见性必须断言**计算样式**，禁止断言「元素存在」。测插件扩展必须经**真实 `EditorView`**，禁止 mock `EditorState`。

**理由**：绕过真实路径的测试会**全绿而功能为零**——因为 bug 恰好落在被绕过的那几跳里。

**违规真实案例**：`#174` 的测试写作 `handleAutoPair(view, '**')` 直接传参调用，绕过 `keydown → keymap → EditorView.inputHandler` **两跳**。而 bug 恰在那两跳：`key: '**'` 是**非法 CM6 键名，被静默丢弃**。测试全绿，真实按键**零配对**。修正后改用 `EditorView.inputHandler` 才生效。

**如何验证**：review 时逐条读测试，确认断言落在公共入口。正反例见 §四。

---

### QG-5 独立验证 + 原始证据

**规则**：每个任务的完成声明，必须附**验证者自己的探针的原始输出**。未粘贴原始观察证据的「已完成」**不予采信**。

**理由**：自证无效。修复期抓出 **4 个「自测全绿但实际无效」**的交付，**4/4 全部由独立探针抓出，零例外**。

**违规真实案例（全部为自报「已通过」）**：
| 对象 | 自报 | 独立探针实测 |
|------|------|--------------|
| `#174` 自动配对 | 测试通过 | 绕过 keymap，真实按键零配对 |
| `#176` 有序列表 | 已修复 | 引入回归：数字消失 + 圆点覆盖 `○`/`✓` |
| `#170` 结构面板 | 浏览器冒烟通过 | `useMemo([editorView])` 依赖稳定对象 → 诊断**永不刷新** |
| `#170` 测试 | 408 passed | 残留 `makeMockView is not defined` 半成品文件未被计数，**误报为绿** |

**探针类型清单**：真实按键（驱动输入管线）/ 真实 DOM 计算样式（`getComputedStyle`）/ 真实 XML 解析 / 真实 `EditorView`。

**成本**：本地 e2e 单文件实测约 **16 秒**，成本极低，收益是拦截**最昂贵的缺陷类型**（功能不存在）。

**如何验证**：票上是否有验证者粘贴的原始输出块（非实施者的测试摘要）。

---

### QG-6 集成 checkpoint

**规则**：change 票数 ≥ 6 时，每完成 **≤ 4 票**必须插入一次集成 checkpoint：合并到集成分支 → `pnpm -r build` → **浏览器打开一次** → 记录「现在用户能看到什么」。

**理由**：12 分支并行 + 延迟集成，反复 rebase 使 `index.ts` 冲突解决退化为**机械粘贴 export**。「合并」只意味着 git 层面成功，**从未意味着应用能跑**。集成债被推迟到终点一次性偿还，此时已累积 12 层。

**违规真实案例**：12 张票各自分支 → 反复 rebase → `index.ts` 冲突 → 机械粘贴 export → 从未真正合并运行。

**如何验证**：change 的 checkpoint 记录（每 ≤4 票一条「用户现在能看到什么」的观察记录）。

---

### QG-7 纵向切片

**规则**：G0 拆票时，每条 task 必须满足**纵向切片**——贯穿 schema→API→UI→test 全层、独立可演示可验证。判据：**一张票做完，用户能否看到点东西？不能 → 切错了。**

**理由**：横向（按层）切片下，每层「完成」时**不产生任何用户价值**；层与层之间的接线无人负责；N 张票做完才第一次具备「可用」的可能，而那一刻没人去测。

**违规真实案例**：12 张票按架构层横切——块模型 → 装饰引擎 → 命令注册表 → AI Provider → 章节树 → 工具栏。每层单独「完成」时用户看到的是**零**。

**如何验证**：反向验收判据——若一条 AC 能在**不修改 `apps/web`** 的前提下被满足，说明票切错了。

## 三、QG-1 的固定 AC 格式

面向用户的票，AC 必须包含如下格式的条目（可直接复制）：

```
在 `pnpm --filter @md-bundle/web dev` 打开的页面中，
<具体操作> 之后，<可具体观测的结果>。
验证：apps/web/test/<feature>.spec.ts 通过。
```

**反向验收判据**：若一条 AC 能在**不修改 `apps/web`** 的前提下被满足 → 说明票切错了（触发 QG-7）。

## 四、QG-4 的代码对照

```ts
// ❌ 绕过 keymap 两跳，bug 恰好在那两跳
handleAutoPair(view, '**')

// ✅ 驱动真实输入路径
await view.dispatch(inputEvent(view, '**'))
```

同源补充规则：

- 测 DOM 可见性 → 必须断言**计算样式**，禁止断言「元素存在」
  ```ts
  // ❌ 元素存在即通过，但可能 opacity:0 不可见
  await expect(marker).toHaveCount(1)
  // ✅ 断言真实可见性
  expect(Number(await marker.evaluate((el) => getComputedStyle(el).opacity))).toBe(0)
  ```
- 测插件扩展 → 必须经**真实 `EditorView`**，禁止 mock `EditorState`
  - 依赖 Lezer 语法树的逻辑（如结构诊断）无法被 mock 对象满足，必须用真实实例

## 五、QG-5 的独立验证协议

验证者（orchestrator，非实施者）必须执行：

1. 读**实际 diff**，不只读报告
2. 跑**自己的探针**（不复用实施者的测试）
3. **把原始输出粘贴到票上**（原始 stdout / DOM 快照 / 计算样式值 / 解析错误数）
4. 未粘贴原始观察证据的「已完成」→ **不予采信**

**禁止采信的证据形式**：「测试通过」「已修复」「冒烟正常」——这些是**结论**，不是**证据**。证据必须是可复核的原始观察。

## 六、豁免机制

| 门禁 | 可否豁免 | 条件 |
|------|----------|------|
| QG-1 用户层 AC | ✅ | 票上显式标注 `no-ui-impact` |
| QG-2 e2e 绑定 | ✅ | 票上显式标注 `no-ui-impact` |
| QG-3 接线归属 | ❌ | 不可豁免 |
| QG-4 真实路径测试 | ❌ | 不可豁免 |
| QG-5 独立验证 | ❌ | 不可豁免 |
| QG-6 集成 checkpoint | ✅ | 票数 < 6 时自然不适用 |
| QG-7 纵向切片 | ❌ | 不可豁免 |

**适用 `no-ui-impact` 的票型**：纯重构、纯库内改动、纯文档、纯基建。

**豁免必须由票的作者显式声明，不得默认**。未声明即视为需要遵守 QG-1/QG-2。
