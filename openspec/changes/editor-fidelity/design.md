## Context

`editor-fidelity` 修复的是一类**根因型**体验问题，不是新功能。当前编辑态的实现方式：

- 编辑态用 CodeMirror 6 的**装饰（decorations）逐类近似还原**预览外观（`heading` / `list` / `quote` / `callout` / `table` / `code` 等各一个装饰模块），DOM 用 `.cm-*` 类。
- 预览态用 `@md-bundle/renderer` 的 `renderMarkdown` + `readerCssText` 渲染，DOM 用 `.preview-content *` 类。
- 两者是**独立的实现**，因此存在"两套渲染 + 两套样式"，**必然分叉**——这正是"编辑态不如预览态好看"的根因，也是表格/高亮块一碰就坍缩、标头重复、围栏残留等缺陷的共同温床。

约束：底层必须**永远是 live Markdown 源码**（ADR-0002），光标所在块要可编辑源码。上一轮 change（`editor-doubao-parity`，已归档）已交付手柄/斜杠/表格/高亮块/分栏/快捷键等功能，本轮**不重复实现**，而是在此之上做保真修复 + 根因解法 + 缺陷收口。

## Goals / Non-Goals

**Goals:**
- 让同一段 Markdown 在**编辑态与预览态逐块视觉一致**（渲染 SSOT + 样式 SSOT）。
- 表格 / 高亮块 / 流程图等**不再坍缩为源码**；活动块仍可编辑源码。
- 控件**悬停即显、零点击**；插入菜单二次过滤含二级项、取消无残留。
- 命令面板**单列重设计**。
- D1–D10 全部收口；本轮作为 QG-1..QG-8 的验收靶场。

**Non-Goals:**
- 分享 / 协作 / 同步块 / 多维表格 / 小组件 / AI 类（见 proposal Out of Scope）。
- 三模式工作区、多页签、FSA、主题三态、邀请链接——本轮不动。
- 不追求像素级"与豆包一模一样"；追求的是**编辑=预览**的一致性 + 实证规格的交互保真。

## Decisions

### D1 编辑=预览：逐块调用共享渲染管线（核心架构决策）

**选择**：编辑态按**块**为单位，对每个非活动块调用 `renderMarkdown(blockSource)` 产出与预览/导出**完全相同**的 HTML，插入编辑态 DOM；编辑态内容区套用与预览**同源**的样式作用域（`readerCssText` 等价物）。光标所在块（活动块）改为显示**原始源码**（活动块源码桥），光标离开即回渲染态。

**替代方案**：
- *继续用 CM6 装饰逐类还原*（现状）→ 否决：两套实现必然分叉，且每加一种块就要写两遍，缺陷温床。
- *全编辑器切换为纯 WYSIWYG（milkdown/TipTap）*→ 否决：违反"底层永远是 live Markdown 源码"（ADR-0002，且属产品 OUT 清单）。
- *整篇一次性渲染为预览 HTML、完全隐藏源码*→ 否决：失去 live-source 编辑性；无法定位光标。

**理由**：把"预览怎么渲染"唯一化，编辑态复用同一函数与同一 CSS，分叉从根上消失；活动块源码桥保留了 ADR-0002 的可编辑性。

**性能配套**：逐块**增量渲染 + 缓存**——只有源变更的块重渲染，未变更块复用缓存输出；KaTeX / mermaid 走 `hydrateLazyFeatures` 懒加载，不在每次击键时重跑。

### D2 悬停驱动的控件显隐状态机

**选择**：手柄 / 块菜单 / 空行「＋」/ 子菜单的显隐由**指针位置**驱动（行 / 手柄 / 菜单 / 滚动 / 跨空档均维持），点击只用于"确认动作"。手柄→菜单之间做**命中桥接**（不可见桥接区），移动不消失。块菜单在**悬停手柄**时自动展开。

**替代方案**：点击召唤控件（现状）→ 否决：与实测的豆包 P0「悬停即显、零点击」相悖，且多一次操作。

### D3 图标系统：块型/动作 → `data-icon` 映射表

**选择**：统一 `<svg data-icon="XxxOutlined">`（viewBox 24×24、currentColor），建立"块型→图标""动作→图标"映射表，替换零散字符/简易 SVG。手柄显示**该块自己的类型图标**；空行「＋」= `AddOutlined`；颜色面板用彩色「A」字母。

**理由**：P3「图标即词汇」；映射表让加块型时图标不遗漏、不重复。

### D4 命令面板：单列重设计（显式反转上一轮网格）

**选择**：从 CSS Grid 改为**单列**——图标｜名称｜简介｜…｜键位右对齐；分组吸顶 + 顶部「最近使用」；模糊 + 拼音 + 命中高亮；单列顺序导航（选中态 = 品牌淡底 + 左侧 2px 强调条）；底部键位提示条；空态建议。

**替代方案**：保持上一轮的网格（`repeat(auto-fill,minmax(190px,1fr))`）→ 否决：键位被挤、行不对齐、↑↓ 跨列乱跳。这是**显式反转**，须在相关票面注明。

### D5 表格 / 高亮块：渲染态内联编辑，不坍缩源码

**选择**：表格保持可视化 + 单元格内可编辑；格内手柄悬停→**插入菜单**（非块菜单，教训 T-1）；行/列锚点在**格间线**（边界线高亮）。高亮块卡片内联编辑，标头 = `emoji + label`（不重复），类型/颜色/emoji 走二级菜单。二者均满足 D1 的"预览态渲染 + 活动块源码"。

### D6 缺陷收口路线

D1（打开进编辑）、D3（围栏反引号）、D4（菜单不关）、D5（空态驻留）、D6（取消残留）、D9（空态入口）、D10（React 重复 key）随相关票修复；D2/D7/D8 由 D1+D5 的架构与规格一并解决。全部在票面标注对应 D 编号，供 QG-8 对账。

### D7 验收基建：三分类 AC + 断言阶梯 + 视觉探针

**选择**：每张用户可见票 AC 必含 **存在 / 生命周期 / 保真** 三行（QG-1）；断言落在强度阶梯（存在→可见→文本相等→状态往返→视觉，QG-4）；关键态多态截图 + 复核（QG-5）。测试 seam 复用既有 `apps/web/test/*.spec.ts`（不新建抽象层）。

## Risks / Trade-offs

- **[性能]大文档逐块渲染导致卡顿** → 按块增量渲染 + 缓存；未变更块不重渲染；懒加载重特性（KaTeX/mermaid）；对超大文档设阈值，超阈值块降级为装饰渲染并标记待优化。
- **[光标↔源码映射]活动块在"源码"与"渲染"间切换时定位漂移/闪烁** → 活动块以源码形式承载光标，切换时以块边界为锚点；切换不重建整篇 DOM。
- **[边界吞字]装饰与源码边界处吞输入（历史 D2 边界）** → 活动块块级隔离；末字符后追加的用例进 e2e。
- **[IME 组合态]组合输入中途触发渲染/菜单** → 复用既有 IME 守卫；组合期间不提交渲染、不选命令。
- **[一致性回归]改渲染 SSOT 可能改变既有块外观** → 用"编辑态 vs 预览态计算样式相等"的视觉探针作为验收，逐块比对，回归即红。
- **[范围蔓延]W0 是架构改动，容易吞掉所有票** → W0 单独成票并**先出本 design**；其余保真票可与之并行（在 W0 落地前，表格/高亮块先按"D5 不坍缩"的既有 widget 修复，W0 落地后自动受益）。

## Migration Plan

1. **W0 先行**：本 design 定稿即视为 ADR；实现时按"先接入、后替换"推进——先让编辑态内容区套用共享样式作用域与逐块渲染，保留既有装饰为**回退路径**；单块验证一致后再移除近似装饰。
2. **逐块替换**：一次一块类型（标题 → 列表 → 表格 → 高亮块 → 代码 → 公式/图），每类附"编辑态 vs 预览态计算样式相等"断言。
3. **回退策略**：若某块类型迁移引入回归，将该块类型回退到既有装饰渲染（per-block 开关），不影响整体；缺陷转 `[bug]` 票（DQ 流程）。
4. **收尾**：全部块类型迁移 + D1–D10 收口 + `validate --strict` 通过 → G4 归档。
