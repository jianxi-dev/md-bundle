# MD-Bundle Web

## 目标

MD-Bundle Web 是一个基于浏览器的 Markdown 打包工具，可将图片与附件打包进一个自包含的 `.mdpkg` 文件，从而实现零裂图（图片不会失效）的分享。

## 需求

### 需求：打开 Markdown 与包文件

**状态：** 在 v2 中修改

系统 SHALL（应）支持通过文件选择器和拖拽方式打开 `.md` 与 `.mdpkg` 文件。`md` 文件 SHALL 直接在新标签页的编辑器中打开。`.mdpkg` 文件 SHALL 通过上游的 `openMdpkg` 读取器解包，并经共享 Markdown 渲染器渲染为一个实时预览，该预览会随文档编辑而刷新（v1 中沙箱 iframe 的静态预览已被移除）。包的校验结果 SHALL 展示在校验横幅中，其资源清单展示在左侧栏的 Assets（资源）标签页中。损坏的、schema 非法的或格式不符的文件 SHALL 产生一个优雅、确定的错误状态，且 MUST NOT（不得）崩溃或渲染白屏。

#### 场景：通过文件选择器打开 Markdown 文件
- **当** 用户通过文件选择器选择一个 `.md` 文件
- **则** 文件内容载入新标签页的源码编辑器中

#### 场景：打开包文件并看到实时预览
- **当** 用户打开一个合法的 `.mdpkg` 文件
- **则** 文件被解包，完整预览经共享渲染器渲染，且预览在文档被编辑时刷新

#### 场景：打开损坏的文件
- **当** 用户打开一个字节并非合法包、或包含违反 schema 的 manifest 的文件
- **则** 系统展示一个带有清晰错误信息的错误 UI，且无未捕获异常或白屏

### 需求：带分屏预览与斜杠模板的 Markdown 编辑

**状态：** 在 v2 中修改

系统 SHALL 提供一个 CodeMirror 6 源码编辑器（markdown 语言、受控值、暗色主题），由共享的 `@md-bundle/editor` 库提供。编辑遵循「活源码」（living-source）范式：markdown 始终为唯一事实来源，编辑时的装饰（标题、粗体/斜体、列表、引用、行内代码、行内图片、提示卡片）以可视化方式呈现，但在光标处显示原始 markdown。输入 `/` SHALL 弹出斜杠命令菜单（标题 / 提示卡片 / 图片引用 / 代码块 / 表格 / 引用），在光标处插入 markdown 模板；Esc SHALL 关闭菜单而不插入内容。预览输出的渲染委托给共享 Markdown 渲染器，且嵌入的脚本 SHALL 始终被转义，绝不被执行。原先常驻的分屏预览被显式的三模式工作区（编辑 / 源码 / 预览）取代。

#### 场景：编辑内容反映到预览模式
- **当** 用户在编辑器中编辑 markdown 并切换到预览模式
- **则** 预览显示来自共享渲染器的已渲染 HTML 片段

#### 场景：通过斜杠命令插入标题
- **当** 用户在光标处输入 `/` 并从命令菜单中选择「标题」
- **则** 光标处插入 `## `

#### 场景：Esc 关闭斜杠菜单而不插入
- **当** 用户打开斜杠菜单并按下 Esc
- **则** 菜单关闭且未插入任何模板

#### 场景：嵌入脚本被转义
- **当** 包含 `<script>` 块的 markdown 被渲染为预览
- **则** 脚本被作为文本转义，而不被执行

#### 场景：光标揭示装饰块中的源码
- **当** 用户将光标移入一个可视化装饰的标题或提示卡片块
- **则** 该块的原始 markdown 标记变为可见，且不改变文档值

### 需求：零摩擦图片导入与资产管理

系统 SHALL 通过三个渠道导入图片——剪贴板粘贴、拖拽到编辑器、以及多选文件——最多 2 步，无向导或对话框。每次导入 SHALL 在光标处插入一个 markdown 图片引用，并将图片加入一个资产清单（路径 / 大小 / 缩略图），该清单支持删除与替换。当正文已引用 `![name](name.png)` / `![name](./name.png)` 时，批量导入 SHALL 按文件名自动连线图片。粘贴非图片内容 SHALL NOT（不应）触发导入；重名 SHALL 被自动重命名而不覆盖。

#### 场景：粘贴剪贴板截图
- **当** 用户向编辑器粘贴一张截图图片
- **则** 正文中出现图片引用，且图片被列在资产清单中

#### 场景：粘贴非图片内容
- **当** 用户粘贴文本或其他非图片内容
- **则** 不触发导入，且编辑器内容不受影响

#### 场景：批量导入按文件名连线已有引用
- **当** 正文已包含 `![name](name.png)` 且用户批量选择了一个名为 `name.png` 的文件
- **则** 引用被连线到导入的资产，无需用户进一步操作

#### 场景：重名导入不覆盖
- **当** 用户导入一张名称已存在于资产列表中的图片
- **则** 新图片被自动重命名，且现有资产不被覆盖

### 需求：包校验报告

**状态：** 在 v2 中修改

系统 SHALL 将 `openMdpkg` 返回的校验结果（`validation.ok` / `errors` / `warnings` / `externalCount`）展示在工作区顶部的校验横幅中，并包的资源的清单列在左侧栏的 Assets 标签页中。合法的包 SHALL 显示通过状态；带有错误的包 SHALL 列出每个错误；`externalCount > 0` SHALL 显示外部引用提示。

#### 场景：合法包显示通过状态
- **当** 打开一个合法的 `.mdpkg`
- **则** 校验横幅显示「已通过」状态

#### 场景：非法包列出错误
- **当** 打开一个带校验错误的 `.mdpkg`
- **则** 横幅列出每个错误并显示失败状态

### 需求：格式驱动的 Markdown 源码导出

导出下拉菜单 SHALL 显式提供五种格式：`.md`、`.mdpkg`、Word (`.docx`)、HTML 与 PNG 长图。导出 `.md` SHALL 下载与编辑器内容逐字节相同的源码文本。当文档包含图片时，导出 `.md` SHALL 先警告图片将丢失；取消 SHALL 中止导出。Word 导出 SHALL 由上游 mdpkg `toDocx` 引擎从当前编辑器源码（`document.md`）与每个导入资产的原始字节组装的 files Map 生成，并 SHALL 产出标准 OOXML 文档（含 `[Content_Types].xml` + `word/document.xml` 的 ZIP 容器），其图片作为 `word/media/*` 条目嵌入；产物 SHALL 以 `Blob` 形式下载，文件名由文档名派生（默认 `document.docx`）。空文档 SHALL 仍产出合法非空 `.docx`。导出失败 SHALL 通过导出封装层的确定性 `{ error }` 结果路径呈现，且 MUST NOT 崩溃或渲染白屏。

#### 场景：导出带图片丢失警告的 markdown
- **当** 用户从一个含图片的文档导出 `.md`
- **则** 导出前显示「图片将丢失」警告，且取消后不产生下载

#### 场景：导出空 markdown
- **当** 用户从一个空文档导出 `.md`
- **则** 下载一个空文件且无错误

#### 场景：将文档导出为 Word
- **当** 用户将一个含标题、列表、表格与导入图片的非空文档导出为 Word (`.docx`)
- **则** 下载一个合法 OOXML 文档（ZIP magic 字节 `PK\x03\x04`，存在 `[Content_Types].xml` 与 `word/document.xml`），图片作为 `word/media/*` 条目嵌入，且下载通过导出结果路径完成

#### 场景：将空文档导出为 Word
- **当** 用户将空文档导出为 Word
- **则** 产出合法非空 `.docx` 且无错误

#### 场景：Word 导出中 SVG 图片降级
- **当** 文档包含无法作为 Office 媒体嵌入的 SVG 图片
- **则** 导出以占位替代文本与警告成功，不导致整体导出失败

#### 场景：Word 导出失败被确定性上报
- **当** 导出封装层在生成 `.docx` 时遇到错误
- **则** 封装层返回 `{ error }` 结果（无未捕获异常、无白屏），且 UI 呈现错误信息

### 需求：自包含 HTML 导出

系统 SHALL 导出一个用主题系统渲染的自包含 HTML 文档：所有图片 SHALL 内联为 `data:image/...` URI，零相对路径、`file://` URL 或外部图片引用，并带一个「Made with MD-Bundle」署名脚注，链接到 `https://bundle.jianxi.me/?ref=md-html`。

#### 场景：HTML 导出内联所有图片
- **当** 打开一个含 K 张图片的样例 `.mdpkg` 并导出为 HTML
- **则** HTML 包含 K 个 `<img>` 标签，且全部为 `data:image/...` URI，零破损或外部图片引用

#### 场景：无图片文档的 HTML 导出
- **当** 一个不含图片的 markdown 文档被导出为 HTML
- **则** HTML 不含 `<img>` 标签且无错误地渲染

### 需求：PNG 长图导出

系统 SHALL 通过将主题化 HTML 渲染进 SVG `foreignObject` 再光栅化到 canvas（不使用 html2canvas）来将整篇文档导出为 PNG 长图。CJK 与 emoji 文本 SHALL 渲染而无豆腐块（缺字方块）。空文档 SHALL 产生清晰错误且无损坏 PNG。

#### 场景：导出含 CJK 与 emoji 的文档
- **当** 用户将一个含「中文👍测试」之类文本的文档导出为 PNG 长图
- **则** PNG 非空、尺寸为正，且采样像素显示无豆腐块伪影

#### 场景：将空文档导出为 PNG
- **当** 用户将空文档导出为 PNG 长图
- **则** 系统显示清晰错误信息且不产生损坏 PNG

### 需求：首页主视觉、工具工作区与画廊

**状态：** 在 v2 中修改

首页 SHALL 呈现一个重新设计的主视觉（hero），标语为「分享 Markdown，不再裂图。」，并有一行文字说明产品的格式范围（打开并编辑 `.md`、一键 `.mdpkg` 打包、导出 md·Word·HTML·PNG 长图）、一个产品风格的工作区主视觉图、双行动号召按钮，以及三个价值徽章（仅本地不上传 / 单文件打包 / 复制即分享）。首页 SHALL 包含一个由 session storage 提供数据的「最近文档」区块，以及一个由官方示例文档（含 math+mermaid 的 markdown、含 callout+table 的 markdown、以及带图片的打包 mdpkg）组成的「精选作品」画廊。每张画廊卡片 SHALL 显示真实渲染内容的缩略图，附标题、自动摘要与格式徽章，并在点击时将该示例作为新标签页载入编辑器。缺失的促销资源 SHALL NOT 使主视觉塌陷（有兜底）。

#### 场景：重新设计的主视觉文案与格式范围可见
- **当** 首页加载
- **则** 主视觉标语、格式范围行、产品主视觉图、两个 CTA 按钮与价值徽章均可见

#### 场景：将精选示例载入编辑器
- **当** 用户点击「精选作品」示例卡片
- **则** 该示例作为新标签页在编辑器中打开

#### 场景：缺失促销图时的兜底
- **当** 促销图片资源缺失
- **则** 主视觉仍以兜底方式渲染且布局不塌陷

### 需求：内容驱动保存

**状态：** 在 v2 中修改

主保存按钮 SHALL 是内容驱动的：含图片的文档 SHALL 保存为 `.mdpkg`；无图片的文档 SHALL 保存为 `.md`；从 `.mdpkg` 打开的文档 SHALL 保存回 `.mdpkg`（无缝重打包）。`.mdpkg` 写入 SHALL 复用上游的 `packMdpkg`，使输出符合规格且能通过 `openMdpkg` 往返，内容等价。按钮是写回磁盘、触发「另存为」还是下载，由三层保存模型（FSA 可用性及句柄归属）决定；上述格式选择规则适用于每一条路径。

#### 场景：保存含图片的文档
- **当** 用户保存一个含已导入图片的文档
- **则** 系统生成一个 `.mdpkg` 文件（依三层模型写盘、另存为或下载）

#### 场景：保存无图片的文档
- **当** 用户保存一个无图片的文档
- **则** 系统生成一份编辑器文本逐字节相同的 `.md` 文件

#### 场景：重打包一个包并重新打开
- **当** 一个 `.mdpkg` 被打开、编辑、再次保存并重新打开
- **则** 重打包的包以文件、manifest 与 html 内容与源等价的方式打开，且资产路径、sha256 与媒体类型相匹配

### 需求：署名脚注与「复制为图片」分享卡

**状态：** 在 v2 中修改

系统 SHALL 将一个可点击的小号「Made with MD-Bundle」署名脚注（带 `?ref=` 链接）渲染进导出的 HTML 脚注与 PNG 长图的角落。`.mdpkg` 文件正文 SHALL 保持干净、不含任何品牌信息。本需求的文档级分享能力拆分为两个独立特性：网站的邀请分享卡（见「邀请分享卡」）与文档的「复制正文为图片」按钮。文档复制为图片操作 SHALL 是顶栏操作区最左侧位置的一个专用幽灵图标按钮，SHALL 经共享渲染器将当前文档正文渲染为一张带署名（含网站 URL 与渐隐的 Jianxi 品牌）的 PNG，SHALL 在 Clipboard API 不可用或拒绝时将 PNG 复制到剪贴板并附下载兜底，且 SHALL 在无打开文档时被禁用。邀请卡是网站级的，不消耗当前文档，且在无打开文档时仍可用。

#### 场景：署名出现在导出物中，但不在包字节中
- **当** 从一份文档产生 HTML、PNG 与复制为图片产物
- **则** 每个产物都含「Made with MD-Bundle」署名及其 `?ref=` 链接，且 `.mdpkg` 字节中不含署名字符串

#### 场景：从顶栏按钮复制文档正文为图片
- **当** 用户从最左侧顶栏图标按钮对一份有内容的文档触发复制为图片
- **则** 一个合法的 PNG blob（魔数 `89 50 4E 47`）被交付给剪贴板

#### 场景：剪贴板不可用时兜底下载
- **当** Clipboard API 不可用或被拒绝
- **则** 文档 PNG 改为下载

#### 场景：无文档数据时复制为图片被禁用
- **当** 没有打开的文档
- **则** 顶栏复制为图片按钮被禁用，且不生成空卡片

### 需求：本地分层成就徽章

系统 SHALL 在一个以 localStorage 为后盾、带稀有度层级（Common/Rare/Epic/Legendary）的阶梯上授予本地成就徽章。徽章 SHALL 在真实的 Phase-1 动作完成的那一刻解锁——首次成功 `.mdpkg` 保存、首次 PNG 导出、以及第 N 次导出（层级晋升）——绝不在注册或进入页面时解锁。已解锁状态 SHALL 在重载后保持，重复触发 SHALL NOT 重新解锁或重新弹提示，且损坏的 localStorage 数据 SHALL 安全降级。

#### 场景：首次 PNG 导出解锁徽章
- **当** 用户完成其首次成功的 PNG 长图导出
- **则** `first-png` 徽章解锁并弹出完成提示（toast）

#### 场景：首次包保存解锁徽章
- **当** 用户完成其首次成功的 `.mdpkg` 保存
- **则** `first-pack` 徽章解锁

#### 场景：层级随重复导出晋升
- **当** 用户完成跨越阶梯阈值的第 N 次导出
- **则** 徽章升级到下一稀有度层级

#### 场景：徽章状态在重载间保持
- **当** 用户在解锁徽章后重载页面
- **则** 已解锁徽章与层级状态从 localStorage 恢复

#### 场景：徽章存储损坏时安全降级
- **当** localStorage 徽章数据损坏
- **则** 徽章系统从空默认状态启动而不崩溃

### 需求：SEO 多页静态站点

**状态：** 在 v2 中修改（另见「SEO 示例页」）

系统 SHALL 通过 Vite 多页构建（而非 SPA 客户端路由）构建静态可爬取页面——落地页（`index`）、`/spec`、`/about`，以及每个精选示例文档一页。站点 SHALL 提供 `robots.txt`、`sitemap.xml`、一张 1200x630 的 OG 图、JSON-LD `SoftwareApplication` 元数据，以及指向 `bundle.jianxi.me` 的每页 canonical URL。页面正文内容 SHALL 存在于静态 HTML 中，无需 JavaScript。

#### 场景：静态页可爬取
- **当** 检查所有页面的构建输出
- **则** 每个页面的正文内容与 meta 标签均存在于其静态 HTML 中

#### 场景：sitemap 列出所有页面
- **当** 检查 `sitemap.xml`
- **则** 它包含 `bundle.jianxi.me` 下的落地页、`/spec`、`/about` 与示例页 URL

#### 场景：OG 图尺寸正确
- **当** 检查 OG 图资源
- **则** 其尺寸为 1200x630

### 需求：Vercel 上的静态部署

系统 SHALL 作为静态站点部署在绑定到 `bundle.jianxi.me` 的 Vercel 上。生产环境的落地页、`/spec` 与 `/about` 页面 SHALL 返回 200，且工具 SHALL 在生产环境打开一个官方示例 `.mdpkg`。

#### 场景：生产环境冒烟测试通过
- **当** 冒烟测试在生产环境访问 `bundle.jianxi.me`、`/spec` 与 `/about` 并打开一个示例包
- **则** 三个页面均返回 200，且工具渲染该示例包

### 需求：共享 Markdown 渲染器

**状态：** 在 v2 中新增

系统 SHALL 提供一个共享的 `@md-bundle/renderer` 包，它拥有唯一的 Markdown 渲染管线：marked + DOMPurify 净化（唯一的净化事实来源）、KaTeX 数学、懒加载 mermaid、基于 lezer 的代码高亮、callout 折叠、CJK 间距、frontmatter 剥离，以及图片 figure/zoom 标记。该包 SHALL 导出 `renderMarkdown(markdown, opts)`（一个永不抛出、对不支持的单一特性做降级的纯函数）、`readerCssText`（带 `[data-theme]` 暗/亮变体的阅读器排版）、`calloutTypeMap`（逐字快照的 clairis 源的 callout 键集——22 个键；早先声称 23 个的文档是误数）、以及 `hydrateLazyFeatures(root, theme)`（异步挂载 KaTeX/mermaid 且始终 resolve）。`.md` 实时预览、HTML 导出与 PNG 长图导出 SHALL 全部消费此渲染器；编辑器手写的净化器被移除。仅导出的保真度使用 vendored（内置）的 `mdpkg-web.js` 渲染。

#### 场景：渲染的 markdown 被净化
- **当** 含 script、onerror 处理器、javascript URL 或 iframe 的 markdown 经 `renderMarkdown` 渲染
- **则** 输出 HTML 剥离或转义所有可执行内容

#### 场景：懒加载特性水合进一个游离根节点
- **当** 含数学与 mermaid 占位符的渲染 HTML 在一个游离 DOM 根中水合
- **则** 占位符变为 KaTeX 与 SVG 输出，且即便输入错误该 promise 也始终 resolve

### 需求：活源码编辑器装饰

**状态：** 在 v2 中新增

系统 SHALL 装饰 CodeMirror 编辑器，使 markdown 结构以可视化方式呈现，而文档值保持纯 markdown：标题标记、粗体/斜体分隔符、列表标记、引用块、行内代码、行内图片（带用于替换/删除/定位的悬停操作条），以及 callout 卡片（色调取自渲染器的 `calloutTypeMap`）。装饰 SHALL 仅在 IME 组合之外重算（`view.composing === true` 时跳过，且一次 compositionend 处理会补上），使装饰集在组合过程中永不闪烁。将光标移入装饰块 SHALL 揭示原始 markdown。不支持的 callout 前缀 SHALL 降级为纯文本。在源码模式下，所有装饰 SHALL 经一个 CodeMirror compartment 被禁用。

#### 场景：装饰不改变文档值
- **当** 一个标题在编辑器中被可视化装饰

- **当** 用户在装饰块内组合 CJK 文本

#### 场景：行内图片悬停条提供替换与删除
- **当** 用户悬停编辑器中的行内图片部件
- **则** 出现替换与删除操作，并触发既有资产流

### 需求：多标签页会话持久化

- **当** IndexedDB 写入因配额耗尽而失败
- **则** 会话在内存中继续，并弹 toast 警告而不崩溃

### 需求：FSA 文件夹工作区（Chromium）

**状态：** 在 v2 中新增

系统 SHALL 提供一个文件系统访问（File System Access）文件夹工作区，作为仅 Chromium 的渐进增强：`grantWorkspaceFolder()` 以 readwrite 模式调用 `showDirectoryPicker`；目录句柄持久化于 IndexedDB，重新进入时通过 `requestPermission` 提供一键重新授权，被拒绝的权限降级为隐藏的树加一条提示。文件树 SHALL 从已授权目录递归列出 `.md` / `.mdpkg` / 文件夹（懒展开、手动刷新——无自动变更监视），高亮当前打开文档的节点，并在未授权文件夹时显示带「授权文件夹」CTA 的空状态。点击 `.md` / `.mdpkg` 节点 SHALL 在有写回句柄的新标签页中打开它。所有 FSA 能力函数 SHALL 返回 `{ ok } | { error }` 结果且绝不抛出。在非 FSA 环境中，该特性 SHALL 完全隐藏，且主流程与 v1 等价。系统 SHALL NOT 预置任何系统目录（禁止枚举桌面/下载/文档）。

- **则** 句柄被恢复，且一键重新授权 readwrite 权限

- **当** 用户点击已授权文件夹树中的一个 `.md` 文件
- **则** 文件在新标签页打开，且该标签页持有用于写回的文件句柄

#### 场景：无 FSA 环境隐藏该特性
- **当** 浏览器缺少三个文件系统访问选择器
- **则** 文件树特性被隐藏，且主打开/编辑/保存流与 v1 一致

### 需求：三层保存模型

**状态：** 在 v2 中新增

系统 SHALL 实现一个三层保存模型，顶栏只有一个主按钮（一条规则，无歧义）：（1）持有一个磁盘句柄的标签页——来自 FSA 树、一次打开或一次先前的另存为——SHALL 使按钮显示「Save」并经 `createWritable` 写回原文件，弹 toast「已保存到磁盘」，并清除 dirty 标志；（2）在无句柄的 FSA 能力浏览器中的标签页 SHALL 使按钮显示「Save」并触发带内容驱动扩展名的 `showSaveFilePicker` 另存为，记住返回的句柄；（3）非 FSA 浏览器 SHALL 使同一主按钮位置显示「Download」并执行一次下载。一个独立的「download copy」菜单项 SHALL 仅存在于导出下拉中（自动格式：有图片 -> `.mdpkg`，无图片 -> `.md`，已打开的包 -> `.mdpkg`）。到 IndexedDB 的自动保存 SHALL 始终静默运行作为草稿保护（不计入已保存到磁盘）。dirty SHALL 指未保存到磁盘的更改。用户取消另存为 SHALL 是一次静默取消，返回 `{ ok: false, error: 'cancelled' }`，无错误 toast 且保留 dirty 标志。每一次权限拒绝、写回失败或打包失败 SHALL 返回 `{ ok: false, error }` 加一次 toast，且绝不抛出。

#### 场景：写回原文件清除 dirty
- **当** 保存一个持有磁盘句柄的标签页
- **则** 字节经模拟句柄写回原文件，且 dirty 标志清除

#### 场景：无 FSA 的主按钮执行下载
- **当** 浏览器缺少 FSA 选择器且用户激活主按钮
- **则** 主按钮显示「Download」并执行一次下载

#### 场景：另存为取消是静默的
- **当** 用户取消另存为选择器
- **则** 操作返回 cancelled，无错误 toast 且 dirty 标志保留

### 需求：网站邀请链接（InviteView）

- **当** 用户复制一个邀请链接

- **当** 访客打开一个邀请链接
- **则** 页面将受邀者昵称作为主视觉、显示网站 URL 文本，且 CTA 打开预载了示例文档的编辑器

#### 场景：格式错误的邀请参数优雅兜底
- **当** URL 含缺失或非法的 `ref` / `by` 值
- **则** 渲染正常落地页而无错误
