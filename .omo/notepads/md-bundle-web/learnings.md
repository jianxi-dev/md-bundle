## [2026-09-05T02:20:00+08:00] Task 1.5 preview hardening

- **Mechanism chosen (3 layers, no new deps)**:
  1. Escape-in-source: `markdown.replace(/<\/?script/gi, m => m.replace('<', '&lt;'))` BEFORE `marked.parse` — covers `<script>`, `<SCRIPT>`, `<script\n`, and closing `</script` (baseline only did `<script`; closing tags now escaped too so no stray `</script>` in output).
  2. `renderer.html` override (marked v14: `new marked.Renderer()` + assign methods; parser sets `renderer.parser` at parse start, so captured `defaultLink.call(renderer, {...})` works): regex-based tag sanitizer `sanitizeRawHtml` — removes dangerous tags entirely (open+close): `script|iframe|object|embed|link|meta`; strips `on*` event-handler attrs; neutralizes `javascript:`/`vbscript:` in `href|src|action|xlink:href|formaction` (→ `attr=""`). Safe tags (`div`, `span`, `img`, `table`…) pass through.
  3. `link`/`image` renderer overrides: dangerous-scheme href → `''` (covers markdown links, autolinks `<javascript:...>`, reference links, images).
- **URL scheme check**: browsers strip ASCII whitespace + control chars before parsing schemes (`java\tscript:` = `javascript:`), so `stripUrlJunk` removes `[\u0000-\u0020\u007f]` before the `^(?:javascript|vbscript)\s*:` test.
- **Tag regex**: `HTML_TAG = /<\/?[a-zA-Z][^<>]*(?:"[^"]*"[^<>]*)*(?:'[^']*'[^<>]*)*>/g` tolerates `>` inside quoted attribute values; `HTML_ATTR` handles double/single/unquoted values.
- **marked v14 verified behaviors** (empirical, node script): text `&lt;script>` is NOT double-escaped in paragraphs (`<p>&lt;script&gt;…`), but IS double-escaped inside code spans (`<code>&amp;lt;script&gt;</code>`) — so inline-code/fenced-code tests assert `textContent`/`&amp;lt;` forms, not `&lt;`. Image `alt` IS escaped by default (`"` → `&quot;`) — no alt breakout. `cleanUrl` only encodeURI-validates — does NOT block `javascript:` (must block ourselves). Renderer methods are invoked as `this.renderer.html(token)` so `this` = renderer instance.
- **Cosmetic tradeoff (documented)**: escape-in-source means fenced code containing literal `<script>` displays `&lt;script>` (entity) instead of `<script>` — security-first choice; test asserts inert `<pre><code>` + no raw tag, not exact display.
- **TS gotchas**: `marked.Renderer` is exported as a VALUE only (`_Renderer as Renderer`) — type annotation must be `InstanceType<typeof marked.Renderer>`. Overriding `renderer.link` with a partial token object fails TS (needs `type/raw/text`) — spread `{...token, href: safeHref}`.
