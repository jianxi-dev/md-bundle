Markdown 文档平台 — 需求规划

基于：editor-design-final-report.md（Oracle + Momus + Librarian 综合评审） 日期：2026-09-17 状态：待确认

一、产品定义

1.1 一句话定位

创建、分享、阅读自包含文档的最佳方式。

1.2 核心概念

概念 说明
产品 .mdpkg — 可运行的文档工件（不是编辑器）
手段 编辑器 — 创建和编辑 .mdpkg 的工具
体验 “打开一个文件就得到完整体验” — 零安装、零上传、离线
护城河 同源渲染 + 零后端 + 中文原生 + 隐私优先

1.3 目标用户（楔子人群）

需要把带图的文档发出去、又不想上传云端的人。 - 自媒体作者、内部报告撰写者、中文技术写作者

二、需求边界：做什么 / 不做什么

2.1 ✅ 要做（v1）

# 需求 优先级 说明
R1 安全底座修复 P0 DOMPurify 修复 + CSP + API key 内存存储
R2 .mdpkg 即应用 P0 包内自带渲染器 + CSS，双击打开即成品
R3 Diff-native AI P1 选中 → 改写 → 行内 diff → Tab/Esc
R4 结构体检 P1 AST 规则诊断（论点无证据/章节无结论/层级跳跃）
R5 章节重组 P1 拖拽章节重排 + 导出子树
R6 语义编辑态 P2 渐进式语法揭示（块级语义化）
R7 上下文工具栏 P2 根据选中内容/光标位置动态变化
R8 智能输入 P2 Markdown 快捷输入 + 智能 Enter/Backspace + 自动配对
R9 视觉模板库 P2 Callout 12+ 类型 + Hero/Card/Timeline/CTA
R10 HTML 块嵌入 P3 安全 HTML 子集 + @scope 隔离
R11 CSS-only 组件 P3 折叠/标签/进度条（CSS-only，无 JS）
R12 流式编辑 P3 打字即渲染 + 选择即操作

2.2 ❌ 不做（v1 明确排除）

项 理由
意图引擎（主动 LLM 建议） 注意力税，负体验
文档指纹 昂贵/过期/隐私冲突
动态内容块 + 数据源 违反零后端
AI 代理（静默自主） 信任成本 > 收益
内联 SVG XSS 攻击面
自定义元素（md-tabs 等） 与”无私有语法”冲突
导出时剥离增强层 破坏 round-trip
协作编辑（多人实时） 与”零后端”冲突
插件系统 v1 聚焦核心体验

三、功能需求详细规格

R1：安全底座修复（P0）

R1.1 DOMPurify 修复

当前问题 修复 验证
style 属性已允许 从 ALLOWED_ATTR 移除 测试：<div style="x"> 被剥离
id 属性已允许 从 ALLOWED_ATTR 移除 测试：<div id="x"> 被剥离
ALLOW_DATA_ATTR: false 改为 true 测试：data-callout 保留
SANITIZE_NAMED_PROPS 未启用 启用 测试：<a name="cookie"> 被净化

R1.2 CSP 配置

Content-Security-Policy:
  default-src 'self';
  img-src 'self' data: blob:;
  style-src 'self' 'unsafe-inline';
  script-src 'self';
  object-src 'none';
  base-uri 'none'
  • Vercel：vercel.json 加 headers
  • GitHub Pages：<meta http-equiv> fallback

R1.3 API Key 存储

  • 仅存内存（页面刷新即需重输）
  • 绝不入 localStorage / sessionStorage / IndexedDB

R1.4 CSS 隔离

  • 编辑器侧 HTML widget 用 @scope 或 Shadow DOM
  • 防止用户 class 命中 .cm-*

R2：.mdpkg 即应用（P0）⭐ NS-1

R2.1 包格式升级

当前 .mdpkg = zip( manifest.json + document.md + assets/* )
目标 .mdpkg = zip( manifest.json + document.md + assets/* + renderer/ + styles/ )

职责划分：包格式升级由本项目主导实施。上游 mdpkg 规范（jianxi-dev/mdpkg）定义基础结构（manifest + entrypoint + assets），本项目在其基础上扩展 renderer/ 和 styles/ 目录。具体做法： - 复用现有 buildHtmlDocument（exportHtml.ts）生成自包含 HTML - 复用现有 packMdpkg（vendored）打包 - 渲染器 = 内联的 renderer.js（从 @md-bundle/renderer 构建的 UMD bundle） - 样式 = 内联的 styles.css（从 readerCssText 提取）

R2.2 打开方式

方式 行为
拖入编辑器 编辑态（完整功能）
双击 .mdpkg 调用 viewer.html 只读渲染
导出 HTML 单文件自包含 HTML

R2.3 验收标准

R3：Diff-native AI（P1）⭐ NS-2

R3.1 交互流程

用户选中文本 → 点击"AI" → 选择操作（改写/缩短/翻译/结构化）
→ AI 生成提案 → 行内 diff 渲染（绿增红删）
→ Tab 接受 / Esc 拒绝 / ⌘↵ 全接受

AI Agent 接入窗口：v1 不设计独立的 Agent 对话窗口。AI 操作通过以下方式触发： - 浮动工具栏 AI 按钮：选中文本 → 工具栏出现 ✨AI 按钮 → 点击展开操作菜单 - 斜杠命令 /ai：输入 /ai → 展开 AI 操作面板 - 右键菜单：右键选中文本 → “AI” 子菜单

v1 聚焦”选中→改写→diff”这一条路径，不做全文自主编辑的 Agent 模式。Agent 模式（批量改写 + 强制 diff 审阅）推迟到 v2。

R3.2 数据结构

interface AIProposal {
  range: { from: number; to: number }  // 选中文本范围
  original: string                     // 原文
  proposed: string                     // AI 建议
  rationale: string                    // 为什么这样改
  status: 'pending' | 'accepted' | 'rejected'
}

R3.3 Provider 模型

Provider 说明 默认
LocalProvider 端侧 WebGPU/WASM ✅
BYOKeyProvider 用户自己的 API Key 可选
Disabled 完全无 AI 可选

R3.4 验收标准

R4：结构体检（P1）⭐ NS-3 的一部分

R4.1 诊断规则（v1 规则集，零 LLM）

零 LLM 实现方式：所有诊断规则基于 Lezer Markdown AST 的结构化分析，不需要任何 AI 调用。

实现步骤： 1. 解析文档为 Lezer AST（ensureSyntaxTree） 2. 遍历 AST，构建文档结构模型（标题层级、段落列表、列表项、引用块） 3. 对每条规则编写纯函数检测器（输入 AST 片段，输出诊断结果） 4. 诊断结果缓存于 StateField，文档变更时增量更新 5. 诊断结果以行内 decoration 渲染（类似 lint 波浪线）

规则 检测逻辑 严重度
论点无证据 段落含”因此/所以/综上”等结论词，但后续 2 段内无列表/引用/表格 warning
章节无结论 H2/H3 章节超过 3 段，且最后一段不含总结性关键词 info
重复论点 不同章节的标题 Jaccard 相似度 > 0.6 warning
标题层级跳跃 标题层级差 > 1（如 H1→H3） error
超长段落 单段超过 300 字 info
列表项长度失衡 列表中最长项 / 最短项 > 5 info
空标题 标题节点后紧跟另一个标题节点（中间无内容） warning
孤立的图片 图片前后各 2 行无正文段落 info

R6.1 视觉规则

语法 非活动块 活动块 过渡

斜体 * 完全隐藏 完全隐藏 无

R6.2 交换方式（触发/退出语义态）

核心原则：操作必须零学习成本、零鼠标移动。参考豆包的交互模式。

操作 方式 说明
进入语义编辑 光标进入块 光标移动到任意块 → 该块自动切换为语义态（标记淡化显示）
退出语义编辑 光标离开块 光标移出块 → 该块恢复完全渲染态
临时查看源码 Ctrl/Cmd + 点击 点击块内任意位置 → 临时切换为完整源码态，松手恢复
锁定语义态 Ctrl/Cmd + Shift + E 切换当前块在”语义态”和”源码态”之间锁定
全局切换模式 工具栏 ghost 图标 在”编辑（语义）/ 源码 / 预览”三种全局模式间切换
块操作菜单 块手柄 ⠿ 或 / 悬停块左侧出现手柄 → 点击展开块操作菜单

任务语法（Task List）

任务列表是 Markdown 的 GFM 标准语法，本编辑器原生支持交互。

语法 渲染 交互
- [ ] 待办 ☐ 待办 点击 checkbox 切换完成状态
- [x] 已完成 ☑ 已完成 点击 checkbox 切换为待办

交互方式： - 在编辑器中：checkbox 可直接点击切换（不进入源码编辑） - 在预览态：checkbox 同样可交互 - 在语义编辑态：- [ ] 以淡色前缀显示，checkbox 仍可点击

R10：HTML 块嵌入（P3）

允许的 HTML 标签

结构：div, section, article, aside, p, span, br, hr
文本：mark, ins, del, kbd, samp, var, em, strong
交互：details, summary
媒体：img, figure, figcaption
列表：ul, ol, li
表格：table, thead, tbody, tr, th, td

禁止的 HTML 标签

script, style, form, input, button, iframe, object, embed, link, svg(v1)

CSS 隔离

  • 编辑器侧：@scope 或 Shadow DOM
  • 预览侧：已有 .preview-content + contain
