2 智能输入：块级快捷方式

在下方输入框输入快捷语法 + 空格 → 真的会转换。关键：转换后光标仍在块内可继续输入。

输入演示（真的可以输入）
试试输入：#+空格 · ##+空格 · ###+空格 · -+空格 · 1.+空格 · >+空格 · - [ ]+空格 · ```+回车
↑ 点击输入框，输入 ## 然后按空格
关键交互原则
  • 转换 ≠ 锁定：转成 H2 后光标在标题文字处，可以继续输入标题内容
  • 层级可调：标题行按 Tab 降级、Shift+Tab 升级
  • Callout 可继续：输入 > [!tip] + 空格 → 变 callout，光标在内容区
  • 折叠标记可输入：> [!tip]- 默认折叠，+ 展开
  • 任务列表优先：- [ ] + 空格 先于 - + 空格 识别
你在实机测试中报告的问题：
❌ "输入一个 # 后就自动变为标题1，无法输入二三级" → 应该光标可继续输入，Tab 可调层级
❌ "输入 > [!tip] 后就自动识别成 callout，无法再输入 -" → 应该允许输入折叠标记
❌ "输入 - 空格，就变为无序列表，无法再识别任务格式" → 应该支持 - [ ]
❌ "不会自动配对"（** / 「）→ 应该自动配对
❌ "输入 / 有时会自动变成、/" → 应该只在空行行首且非 IME 组合期触发

7 三种模式的完整定义

模式看到什么适合场景

源码完整 Markdown 源码 + 语法高亮精确控制、批量编辑

你在测试中看到"始终是源码"，说明默认状态或渲染逻辑有问题。

8 你新报的 3 个实机问题

1. Cmd+K 无面板 → 实机未接入 UI（库代码存在）。原型第 5 节已实现。

2. 输入 / 有时变成 、/ → 怀疑根因：中文输入法把 / 全角化， 或被 IME 组合期误触发。原型只在空行行首且非组合期触发斜杠菜单。

3. 删内容后格式删不掉，再删又出现已删内容 → 高度可疑：装饰（Decoration）范围未随 文本删除正确映射，导致"幽灵内容"。这是实机最需要优先定位的缺陷。
