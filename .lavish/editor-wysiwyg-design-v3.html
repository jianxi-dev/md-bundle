0. 执行摘要

核心判断：方案方向（AI 原生、结构感知、富表现力）是对的，但存在战略定位偏差和技术安全硬伤。最大问题不是缺功能，而是把"编辑器"当成了产品——真正的产品是 .mdpkg 这个可运行的文档工件。

四维评分

战略定位⚠️→❌在"编辑器"红海中竞争，忽略 .mdpkg 蓝海
创新度⚠️五项"核心创新"中三项已有实现
安全模型❌DOMPurify 配置有事实性错误；全仓无 CSP
可实施性❌组件模型"静态 vs 交互"自相矛盾
一句话建议：暂停功能堆叠，用两周做三件事：(1) 把 .mdpkg 变成"双击就能打开的富文档"；(2) 修掉安全底座；(3) 只做"选中→AI 改写→diff 审阅"这一条 AI 路径。

1. 战略重定位：从"编辑器"到"文档平台"

当前方案的隐含假设：要做一个比 Typora / Obsidian / 豆包更好的编辑器。这个战场打不赢。

我们真正的、别人抄不走的资产

资产说明
.mdpkg 自包含格式图片/附件打包进单文件，跨工具可移植
共享渲染管线 SSOT@md-bundle/renderer 同时服务编辑/预览/HTML/PNG
零后端、本地优先豆包/WorkBuddy 结构性无法承诺
中文原生IME guard、CJK 间距、全角标点已在代码里
重定位后的产品定义："创建、分享、阅读自包含文档的最佳方式。"
编辑器是手段；.mdpkg 是产品；"打开一个文件就得到完整体验"是体验。

2. 五大突破性创新

B1. 文档工件化：.mdpkg = 可直接打开的离线应用 最强
把 .mdpkg 从 zip(md + assets) 升级为 zip(md + assets + renderer + css)。
杀手级结果：发给任何人，对方点开即成品，零安装、零上传、离线。
成本：Medium · 护城河：格式网络效应
B2. Diff-native AI：每次修改都是可审阅事务 信任
AI 产出永远以 inline diff 提案出现：{ range, original, proposed, rationale }
UI：行内 diff（绿增红删），Tab 接受 / Esc 拒绝。
第一次有写作工具让 AI 修改"值得信任"。
成本：Short–Medium · 护城河：信任 = 留存
B3. 隐私账本 + 端侧优先 AI 隐私
默认端侧（WebGPU/WASM 小模型）；任何云端调用必须逐次授权。
Privacy Ledger 面板：每次 AI 动作记录发送了什么、去了哪里。
成本：Medium · 护城河：对豆包的结构性优势
B4. 论证图，而非大纲 独特
理解文档的论证结构，主动指出：论点无证据、章节无结论、重复论点、层级跳跃。
v1 完全不需要 LLM：规则跑在 Lezer AST 上，零成本、零延迟、离线。
成本：Short + Medium · 护城河：竞品空白
B5. 静态声明式组件：零构建的 MDX 替代品 开放
组件 = 纯函数 (props) => HTML 字符串，产物是纯静态 HTML + CSS。
交互只用 CSS-only（details/summary、:target、:checked+label）。
可导出、可离线、可安全。
成本：Short–Medium · 护城河：纯浏览器、零构建

3. 安全硬伤修复 Phase 0 必做

当前代码已存在的漏洞（非未来风险，是今天就能被利用的）：
漏洞位置风险
style 属性已允许markdown.ts:58-64任意 CSS 注入
id 属性已允许同上DOM clobbering
ALLOW_DATA_ATTR: false同上组件 data-* 被剥离
全仓无 CSPvercel.json 无 headers数据外泄无防线

修复清单

  1. 移除 style 从 ALLOWED_ATTR（富样式改走 class 白名单）
  2. 开 ALLOW_DATA_ATTR: true + SANITIZE_NAMED_PROPS: true
  3. SVG 明确列入禁止（v1），或引入专门净化
  4. Vercel 加 CSP headers：img-src 'self' data: blob:
  5. API key 绝不入 localStorage（仅存内存）
  6. CSS 隔离：编辑器侧 HTML widget 用 @scope 或 Shadow DOM

PNG 栅格化安全子集

exportPng 走 foreignObject + SVG-as-image，处于安全静态模式。
❌ light-dark() → 退化为 light · ❌ 网络字体 → tofu · ❌ position:sticky → 被裁
✅ 显式颜色值 · ✅ linear-gradient · ✅ grid · ✅ flex

4. HTML/CSS 嵌入：从"三层"到"三轴"

原"三层增强"的问题

  • 层是叠加关系，隐含"上层可任意加码"
  • 与"无私有语法"硬约束冲突（md-tabs 是私有元素）
  • render: () => string 只能产出静态 HTML，无法交付"交互"

建议的三轴模型

轴说明选项
① 作者语法唯一一套标注方式Pandoc fenced div + Obsidian callout + 标准 HTML
② 呈现视觉样式设计令牌 + class 白名单
③ 能力交互级别静态(CSS-only) | 沙箱(iframe) — 显式二选一

导出语义（简化到一条规则）

导出 = 渲染到目标格式；源始终保留全部信息。
.md = 原文（含注释）· .html/.pdf/.png = 富渲染 · .mdpkg = 原文 + 资产 + 渲染器
没有"剥离"这一步。 HTML 注释在所有渲染器中不可见，剥离只换来 round-trip 破损。

CSS 隔离三层

层机制用于
L1class 白名单（禁 style）所有用户 HTML
L2@scope 或 Shadow DOM编辑器内 HTML widget
L3sandbox iframe（无 allow-same-origin）不可信来源的 .mdpkg

5. AI 功能：去伪存真

保留 ✅

选中 → 改写/缩短/翻译范围明确、可 diff、可撤销
选中 → 结构化（列表/表格）确定性映射 + AI 润色
结构诊断（论证 lint）零成本、离线、可解释
端侧 AI 优先隐私叙事的核心

砍掉 ❌

意图引擎（主动 LLM 建议）砍注意力税（Clippy 模式）
文档指纹砍昂贵/过期/隐私冲突
动态内容块 + 数据源砍违反零后端
md-tabs 等交互组件砍CSS-only 或 iframe 二选一
内联 SVG砍 v1XSS 面

给决策者：
这份方案近 1200 行，描述了一个"功能极其全面"的编辑器。但它回答的是"我们还能加什么"，而不是"用户为什么非我们不可"。

真正的答案已经写在自己代码里了：.mdpkg（可移植的文档工件）、@md-bundle/renderer（编辑=导出的同源渲染）、零后端（文档永不外发）、中文原生。这四张牌，竞品一张都打不出来。

编辑器手感是入场券，不是胜负手。胜负手是：你发出去的那个文件，别人能不能打开、敢不敢打开、打开后像不像你想要的。
